# Нагрузочное тестирование Restful-Booker (k6)

Готовый комплект для практической работы по нагрузочному тестированию REST API. Внутри: исходники Restful-Booker из архива, сценарий k6, автоматический запуск двух уровней нагрузки и генератор Markdown-отчёта.

## Требования

- Docker с рабочим Docker Compose v2 (`docker compose version`);
- Python 3;
- `curl` и Bash (Linux/macOS или WSL под Windows);
- Интернет при первом запуске для скачивания образов и npm-зависимостей.

Устанавливать k6 отдельно не нужно: тест запускается из Docker-образа `grafana/k6:latest`. Внутри контейнера k6 использует общую сетевую среду с контейнером REST API.

## Запуск

Откройте терминал в папке этого комплекта и выполните:

```bash
chmod +x run_all.sh
./run_all.sh
```

Скрипт самостоятельно:

1. Собирает оригинальный Restful-Booker и запускает его локально.
2. Дожидается ответа `/ping` (код `201`), проверяет список бронирований.
3. Сбрасывает состояние сервера, выполняет **10 VUs, 150 секунд**.
4. Сбрасывает состояние сервера повторно, выполняет **40 VUs, 150 секунд**.
5. Сохраняет JSON-метрики и журналы k6.
6. Заполняет `REPORT.md` на основании реальных измерений.

В отчёте будут количество запросов, RPS, среднее время ответа, p95, p99, доля ошибок, таблицы по endpoint и ответы на все 9 вопросов ТЗ.

Важно: код возврата k6 может быть ненулевым из-за нарушенного threshold — это полезный результат теста, а не повод прерывать сбор метрик. Скрипт сохраняет файл `*-exit-code.txt` для каждого запуска.

## Файлы

- `load_test.js` — сценарий k6;
- `LOAD_PROFILE.md` — описание профиля нагрузки и критериев до результатов;
- `run_all.sh` — полный запуск;
- `generate_report.py` — генератор отчёта из JSON;
- `REPORT.md` — отчёт (первоначально с незаполненными фактическими измерениями);
- `restful-booker-main/` — исходный проект;
- `results/` — результаты запусков (появятся после исполнения скрипта).

## Ручная проверка сервера

```bash
cd restful-booker-main
docker compose up --build -d
curl -i http://localhost:3001/ping
curl -i -H 'Accept: application/json' http://localhost:3001/booking
```

Ожидается статус `201` для `/ping` и JSON-массив для `/booking`.

## Профиль и критерии

- 50% `GET /booking`, 30% `GET /booking/:id`, 20% `POST /booking`;
- 30 с ramp-up, 90 с plateau, 30 с ramp-down;
- пауза 0,2–0,5 с;
- p95 < 500 мс, HTTP-ошибки < 1%, ошибки сценариев < 1%.

При оценке помните, что Docker и k6 запущены на одном компьютере, а график VUs закрытого типа не гарантирует фиксированное число RPS. Если обновляется объём данных или меняются ресурсы компьютера, метрики могут отличаться.
